# Руководство по разработке VortexDL

Технический обзор архитектуры бэкенда, базы данных, пайплайнов загрузки и фронтенда VortexDL.

---

## 1. Структура проекта

VortexDL разделен на **Rust Бэкенд** и **Angular Фронтенд**, которые при финальной сборке упаковываются в один исполняемый файл.

```
├── Cargo.toml                  # Зависимости бэкенда
├── build.rs                    # Компилирует фронтенд при активной фиче web
├── Justfile                    # Список команд разработки (install, backend, frontend, dist)
├── src/                        # Исходный код бэкенда на Rust
│   ├── main.rs                 # Минимальная точка входа (Args parse -> app::run)
│   ├── app/                    # Жизненный цикл приложения, AppState, bootstrap и фоновые задачи
│   ├── api/                    # REST API, WebSocket и Swagger UI обработчики
│   ├── cli/                    # Команды и аргументы терминального режима
│   ├── downloader/             # Очередь загрузок, пул воркеров, отмена и финализация
│   ├── providers/              # Стриминговые провайдеры (SoundCloud, YouTube)
│   ├── library/                # Сканер медиафайлов, чтение/запись тегов и индекс библиотеки
│   ├── devices/                # Реестр устройств, транспорт ADB и инкрементальная синхронизация
│   ├── backup/                 # Резервное копирование и снимки настроек (Local, URL, WebDAV)
│   ├── settings/               # Модели настроек и реактивный SettingsManager
│   ├── infra/                  # Инфраструктура (хранилище redb, HTTP-клиент, пул прокси, логирование)
│   ├── domain/                 # Доменные сущности (Track, AudioFormat, Platform)
│   └── terminal/               # Спиннеры и прогресс-бары в консоли
└── frontend/                   # Одностраничное приложение на Angular 21
```

## 2. Архитектура бэкенда

Бэкенд организован по слоистой архитектуре с направлением зависимостей строго сверху вниз:
Адаптеры (`api`, `cli`) → Приложение (`app`) → Оркестрация (`downloader`) → Доменные сервисы (`providers`, `library`, `devices`, `backup`, `settings`) → Инфраструктура (`infra`) → Чистые типы (`domain`, `terminal`).

### А. Инфраструктура и база данных (`src/infra/`)
Работает на чисто Rust встраиваемой СУБД [redb](https://github.com/cberner/redb). Сохраняет конфигурацию пользователя и кэшированные метаданные аудиофайлов. Предоставляет сетевые клиенты, пул fallback-прокси и структурированное логирование.

### Б. Каталог библиотеки (`src/library/`)
Рекурсивно сканирует директорию с аудиофайлами, считывает ID3-теги и аудиометаданные, кэширует результаты в redb и поддерживает оперативный индекс `Library` в памяти.

### В. Пайплайн загрузки треков (`src/downloader/`)
Координирует многоэтапную загрузку с контролем параллелизма, каналами отмены и WebSocket-событиями прогресса:
1.  **Очередь и поиск (`pipeline.rs`)**: Поиск и резолв треков через `providers` (SoundCloud, YouTube).
2.  **Пул воркеров (`worker.rs`)**: Параллельная загрузка аудиопотоков с контролем скорости и сигналами отмены.
3.  **Финализация (`finalize.rs`)**: Запись ID3-тегов, обновление кэша и индекса библиотеки, запуск синхронизации с устройствами.

### Г. Синхронизация с устройствами (`src/devices/`)
Отслеживает подключенные плееры и смартфоны через сокеты ADB-демона (`host:track-devices`):
1.  Сканирует внутреннюю память и SD-карты на устройстве.
2.  Вычисляет дифференциал с локальной библиотекой: передает новые треки (`Артист/Трек.mp3`) и удаляет удаленные локально.
3.  Отправляет Android-команду `media scan` для мгновенного обновления библиотек в музыкальных плеерах.

## 3. Архитектура фронтенда (`frontend/`)

Написан на **Angular 21** с использованием самостоятельных компонентов (standalone components) и сигналов (Angular Signals) для управления состоянием.

### А. Структура исходного кода
*   `src/app/pages/`: Компоненты страниц:
    *   `dashboard-view/`: Главная панель с полем ввода ссылок и прогресс-барами активных загрузок.
    *   `music-tracks-view/`: Каталог локальных треков с поиском, фильтрацией и сортировкой.
    *   `settings-view/`: Управление настройками бэкенда и списком ADB-устройств.
*   `src/app/services/`: Сервисы бизнес-логики:
    *   `download-tracking.service.ts`: Менеджер очереди и SSE-потока событий.
    *   `player.service.ts`: Управление встроенным плеером.

### Б. Управление состоянием (Angular Signals)
Все реактивные переменные (активные прогресс-бары, список треков, поисковые запросы) реализованы через легковесные Angular Signals (`signal()`, `computed()`), что минимизирует лишние перерисовки интерфейса и отказ от громоздкого RxJS там, где это оправдано.

### В. Поток событий реального времени (SSE)
Сервис `DownloadTrackingService` открывает постоянное соединение Server-Sent Events с эндпоинтом бэкенда `/api/download/events` через стандартный браузерный API `EventSource`. 
Сервис парсит JSON-события от Axum, на лету обновляет прогресс-бары в UI и автоматически добавляет успешно скачанные треки в общий реактивный список без перезагрузки страницы.

## 4. Быстрые команды для разработчика

Управление процессами разработки осуществляется через `Justfile`:

```bash
# Установить зависимости бэкенда и фронтенда
just install

# Запустить бэкенд в режиме автоматической перезагрузки при изменении кода (API на порту 3200)
just backend

# Запустить фронтенд-сервер Angular (с горячей перезагрузкой на порту 4200)
just frontend

# Отформатировать исходный код бэкенда и фронтенда
just fmt

# Запустить линтеры кода
just lint

# Собрать готовый оптимизированный релизный бинарник со встроенной веб-панелью
just dist
```
