# Руководство по разработке VortexDL

Технический обзор архитектуры бэкенда, базы данных, пайплайнов загрузки и фронтенда VortexDL.

---

## 1. Структура проекта

VortexDL разделен на **Rust Бэкенд** и **Angular Фронтенд**, которые при финальной сборке упаковываются в один исполняемый файл.

```
├── Cargo.toml                  # Зависимости бэкенда
├── build.rs                    # Компилирует фронтенд при активной фиче web
├── Justfile                    # Список команд разработки (install, backend, frontend, dist)
├── src/                        # Исходный код бэкенда на Rust
│   ├── main.rs                 # Точка входа, инициализация систем, запуск веб-сервера
│   ├── cli.rs                  # Парсинг аргументов CLI-режима
│   ├── settings.rs             # Менеджер настроек приложения (кэш в ОЗУ + запись в БД)
│   ├── storage.rs              # Сканер медиафайлов и индексация локальной библиотеки
│   ├── database/               # Таблицы Redb (settings, sync)
│   ├── api/                    # REST API и обработчик SSE-потоков событий
│   ├── downloader/             # Пайплайн скачивания аудиофайлов
│   └── adb_device/             # Модуль ADB-синхронизации с Android
└── frontend/                   # Одностраничное приложение на Angular 21
```

---

## 2. Архитектура бэкенда

### А. База данных (`src/database/`)
Работает на чисто Rust встраиваемой СУБД [redb](https://github.com/cberner/redb). Сохраняет конфигурацию пользователя и отслеживает состояние чекпоинтов синхронизации для Android-устройств.

### Б. Сканер библиотеки (`src/storage.rs`)
Опрашивает папку с музыкой на диске, извлекает метаданные из названий треков (`Исполнитель - Название`), заносит их в индекс СУБД и предотвращает повторное скачивание уже имеющихся файлов.

### В. Пайплайн загрузки треков (`src/downloader/`)
Конвейер загрузки разделен на 4 изолированных асинхронных этапа (`src/downloader/core/pipeline/`):
1.  **Prepare (`prepare.rs`)**: Инициализирует отображение прогресса в CLI и переводит задачу в `DownloadManager` в статус `Downloading`.
2.  **Resolve (`resolve.rs`)**: Через API SoundCloud находит доступные стриминговые ссылки (Progressive MP3 или HLS-плейлисты).
3.  **Download (`download.rs`)**: Скачивает аудиопоток на диск и передает прогресс в `DownloadManager`.
4.  **Complete (`complete.rs`)**: Записывает ID3-теги (артист, название, обложка) напрямую в MP3-файл, переводит задачу в статус `Finished` и обновляет индекс локальной библиотеки.

### Г. Синхронизация с Android по ADB (`src/adb_device/`)
Каждые 3 секунды асинхронный таймер проверяет подключение разрешенных ADB-устройств. При обнаружении:
1.  Опрашивает файловую систему подключенного плеера/телефона.
2.  Удаляет с устройства **осиротевшие файлы (orphaned)**, которые были удалены локально на ПК.
3.  Копирует **новые треки**, сортируя их по папкам вида `Артист/Трек.mp3`.
4.  Отправляет Android-команду `media scan` на устройство для мгновенного обновления библиотек в музыкальных плеерах.

## 3. Архитектура фронтенда (`frontend/`)

Написан на **Angular 21** с использованием самостоятельных компонентов (standalone components) и сигналов (Angular Signals) для управления состоянием.

### А. Структура исходного кода
*   `src/app/pages/`: Компоненты страниц:
    *   `dashboard-view/`: Главная панель с полем ввода ссылок и прогресс-барами активных загрузок.
    *   `music-tracks-view/`: Каталог локальных треков с поиском, фильтрацией и сортировкой.
    *   `settings-view/`: Управление настройками бэкенда и списком ADB-устройств.
*   `src/app/services/`: Сервисы бизнес-логики:
    *   `download-tracking.service.ts`: Менеджер очереди и SSE-потока событий.
    *   `player.service.ts`: Управление встроенным плеером.

### Б. Управление состоянием (Angular Signals)
Все реактивные переменные (активные прогресс-бары, список треков, поисковые запросы) реализованы через легковесные Angular Signals (`signal()`, `computed()`), что минимизирует лишние перерисовки интерфейса и отказ от громоздкого RxJS там, где это оправдано.

### В. Поток событий реального времени (SSE)
Сервис `DownloadTrackingService` открывает постоянное соединение Server-Sent Events с эндпоинтом бэкенда `/api/download/events` через стандартный браузерный API `EventSource`. 
Сервис парсит JSON-события от Axum, на лету обновляет прогресс-бары в UI и автоматически добавляет успешно скачанные треки в общий реактивный список без перезагрузки страницы.

## 4. Быстрые команды для разработчика

Управление процессами разработки осуществляется через `Justfile`:

```bash
# Установить зависимости бэкенда и фронтенда
just install

# Запустить бэкенд в режиме автоматической перезагрузки при изменении кода (API на порту 3200)
just backend

# Запустить фронтенд-сервер Angular (с горячей перезагрузкой на порту 4200)
just frontend

# Отформатировать исходный код бэкенда и фронтенда
just fmt

# Запустить линтеры кода
just lint

# Собрать готовый оптимизированный релизный бинарник со встроенной веб-панелью
just dist
```
